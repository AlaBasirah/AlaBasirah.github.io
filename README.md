# بصيرة — دليل التشغيل والنشر

موقع يدخل إليه الزائر ويسأل عمّا يُشكل عليه في الدين. تأتي الإجابة **من الكتب التي تحددها أنت فقط**، مع رقم المصدر بعد كل معلومة وذكر الكتاب والجزء والصفحة. وفيه زر «تحدّث مع إنسان» للتواصل المباشر مع مشرف.

## ما الذي يحتويه المشروع

| الجزء | المكان | الوظيفة |
|---|---|---|
| واجهة الزوار | `index.html`, `css/`, `js/` | الشعار، أكثر الأسئلة، زر «تحدّث مع إنسان»، مربع السؤال، «أسئلتي»، «حسابي» |
| لوحة الإشراف والتحكم | `admin/` | للمشرفين: المحادثات والاستفسارات والأسئلة الشائعة. وللمدير فوق ذلك: نظرة عامة بالإحصاءات، وتخصيص كامل للموقع بمعاينة مباشرة، وإعدادات الذكاء الاصطناعي، وتفعيل الكتب، وإدارة الطاقم |
| قاعدة البيانات | `supabase/migrations/001_schema.sql` | الجداول وقواعد الصلاحيات والبحث العربي في الكتب |
| دوال الخادم | `supabase/functions/` | الإجابة المقيدة بالمصادر، طلب المحادثة، تنبيهات البريد، إدارة الطاقم |
| أداة إدخال الكتب | `tools/ingest.py` | تحويل ملفات PDF والنصوص إلى قاعدة معرفة قابلة للبحث |
| الهوية | `assets/` | الشعار (`mark.svg`، `logo-full.svg`) والزخرفة (`pattern.svg`) |

> **لماذا Supabase مع GitHub Pages؟** GitHub Pages يستضيف صفحات ثابتة فقط. أما الذكاء الاصطناعي والمحادثة المباشرة وإرسال البريد والحسابات فتحتاج إلى خادم. Supabase يوفّر ذلك مجانًا في حدود الاستخدام المعتاد.

لمعاينة الشكل دون أي إعداد: افتح الموقع و`js/config.js` فارغ، فيعمل في «وضع المعاينة» ببيانات تجريبية. وكذلك لوحة الإشراف على `/admin/`.

## أولًا: إخفاء هوية المدير والمشرفين (اقرأ هذا قبل كل شيء)

داخل الموقع نفسه لا يظهر للزائر أي اسم أو بريد. رسائل المشرف تظهر باسم «المشرف» فقط، وبريد التنبيهات لا يقرؤه أحد غير المدير. وقواعد قاعدة البيانات تمنع الزائر من رؤية جداول الطاقم أصلًا. لكن **هويتك قد تتسرب من خارج الكود**، فانتبه لهذه النقاط:

1. **حساب GitHub**: رابط GitHub Pages يحمل اسم الحساب (`اسم-الحساب.github.io`)، والمستودع العام يُظهر صاحبه. أنشئ **حساب GitHub جديدًا باسم محايد** (مثل `basira-site`) ببريد مخصص لهذا الغرض، أو اربط نطاقًا خاصًا (Custom domain) مع إخفاء بيانات المالك (WHOIS privacy).
2. **سجل الإيداعات (commits)**: اضبط اسمًا وبريدًا محايدين قبل الرفع:
   `git config user.name "Basira"` و `git config user.email "<رقم>+basira-site@users.noreply.github.com"`
3. **البريد المرسل للمشرفين والزوار** يخرج من عنوان محايد (`MAIL_FROM`) على نطاق ليس باسمك.
4. **لوحة الإشراف** على `/admin/` بلا أي رابط إليها من الموقع، ومحجوبة عن محركات البحث. ويمكنك تغيير اسم المجلد `admin` إلى اسم غير متوقع، لكن عدّل حينها الرابط في `supabase/functions/*/index.ts` (السطر الذي فيه `/admin/`).
5. لا تكتب أسماء حقيقية في محتوى الموقع ولا في أسماء المشاريع على Supabase وResend.

## ثانيًا: إعداد الخادم (Supabase) — حوالي 20 دقيقة

1. أنشئ حسابًا في <https://supabase.com> (بالبريد المحايد) ثم مشروعًا جديدًا.
2. **قاعدة البيانات**: افتح *SQL Editor*، والصق محتوى `supabase/migrations/001_schema.sql` كاملًا ثم *Run*، ثم افعل الشيء نفسه مع `002_settings.sql`.
3. **الدخول**: افتح *Authentication → Sign In / Providers*:
   - فعّل **Allow anonymous sign-ins**. بهذا يسأل الزائر دون تسجيل، وتُحفظ أسئلته في متصفحه.
   - أبقِ **Email** مفعّلًا. منه تأتي الحسابات الاختيارية للزوار وحسابات الطاقم.
   - يُنصح بتفعيل *Captcha protection* (Cloudflare Turnstile) لمنع الإساءة.
4. **الروابط**: في *Authentication → URL Configuration*:
   - Site URL: رابط موقعك، مثل `https://basira-site.github.io/basira`
   - Redirect URLs: أضف `https://basira-site.github.io/basira/**`
5. **بريد الدخول**: خدمة البريد الافتراضية في Supabase محدودة جدًا. من *Authentication → Emails → SMTP Settings* اربط Resend، وهو نفس الحساب في الخطوة التالية: Host `smtp.resend.com`، Port `465`، User `resend`، Password مفتاح Resend. ويمكنك تعريب قوالب الرسائل من *Email Templates*.

### خدمة البريد (Resend)
أنشئ حسابًا في <https://resend.com>، وأضف نطاقًا محايدًا وفعّله، ثم انسخ **API Key**.

### مفتاح الذكاء الاصطناعي (Claude)
أنشئ مفتاحًا من <https://console.anthropic.com> واشحن رصيدًا. السؤال الواحد يستهلك استدعاءين للنموذج: واحد لاستخراج عبارات البحث وآخر للإجابة.

### نشر دوال الخادم
ثبّت أداة Supabase على جهازك (<https://supabase.com/docs/guides/cli>) ثم من مجلد المشروع:

```bash
supabase login
supabase link --project-ref <رمز-المشروع>

supabase secrets set \
  ANTHROPIC_API_KEY="sk-ant-..." \
  CLAUDE_MODEL="claude-sonnet-5-5" \
  RESEND_API_KEY="re_..." \
  MAIL_FROM="بصيرة <noreply@نطاقك>" \
  SITE_URL="https://basira-site.github.io/basira" \
  SITE_ORIGIN="https://basira-site.github.io"

supabase functions deploy ask
supabase functions deploy request-human
supabase functions deploy notify-inquiry
supabase functions deploy notify-visitor
supabase functions deploy admin-staff
```

### ربط الموقع بالخادم
من *Project Settings → API* انسخ **Project URL** و**anon public key** وضعهما في `js/config.js`. هذا المفتاح عام بطبيعته ومحمي بقواعد الصلاحيات. **لا تضع أبدًا مفتاح `service_role` في الموقع.**

### تعيين المدير الأول
1. من *Authentication → Users → Add user* أنشئ مستخدمًا ببريدك المحايد وكلمة مرور قوية.
2. في *SQL Editor* نفّذ:
   ```sql
   insert into public.staff (user_id, role, notify_email)
   select id, 'admin', email from auth.users where email = 'بريدك@هنا';
   ```
3. ادخل إلى `/admin/`. من تبويب «الطاقم» تدعو المشرفين ببريدهم، فتصلهم رسالة لتعيين كلمة المرور.

## ثالثًا: إدخال الكتب (المصادر)

الذكاء الاصطناعي **لا يرى إلا ما أُدخل إلى قاعدة المعرفة**. وكل إجابة تمر بفحص في الخادم: إن لم تكن مستندة إلى مقاطع مسترجعة من كتبك، أو أحالت إلى مقطع غير موجود، تُستبدل بعبارة اعتذار ولا تصل إلى الزائر.

```bash
pip install pypdf
export SUPABASE_URL="https://xxxx.supabase.co"
export SUPABASE_SERVICE_ROLE_KEY="..."        # المفتاح السري، يبقى على جهازك فقط

# فحص الجودة أولًا دون رفع
python tools/ingest.py --author "ابن القيم" "sources/ابن القيم" --dry-run
# ثم الرفع
python tools/ingest.py --author "ابن القيم" "sources/ابن القيم"
```

**كتب ابن القيم (مجلد Google Drive):** نزّل المجلد كاملًا، وهو 54 ملفًا بحجم 1 غيغابايت تقريبًا، وضعه في `sources/ابن القيم/`. اسم الكتاب ورقم الجزء يُستخرجان تلقائيًا من اسم الملف. تنبيه: النص الموجود داخل هذه الملفات **مقلوب الاتجاه** وفيه أخطاء تعرّف ضوئي. الأداة تصحح الانقلاب تلقائيًا وتستبعد الصفحات التالفة وتطبع تقرير جودة لكل كتاب. أما الكتب التي يرفضها التقرير فاستبدلها بنسخة نصية من الكتاب نفسه.

**كتب ابن تيمية (ketabonline):** الموقع لا يتيح تنزيلًا جماعيًا إلا من تطبيقاته. أسهل الطرق للحصول على نصوص نظيفة لكتب ابن تيمية وابن القيم:
- تصدير الكتب نصًّا من برنامج **المكتبة الشاملة**. الأداة تقرأ علامات الصفحات بصيغة `[ص 12]`.
- أو نصوص مشروع **OpenITI** المفتوح (مستودعات `0750AH` و`0775AH` على GitHub). الأداة تقرأ علامات صفحاته `PageV01P012` تلقائيًا.

ضع كل كتاب ملفًا مستقلًا بصيغة `اسم الكتاب ج1.txt`. وكلما كان النص أنظف، كانت الإجابات أدق والمقاطع المعروضة للزائر أوضح.

## رابعًا: النشر على GitHub Pages

1. أنشئ مستودعًا جديدًا (مثلًا `basira`) في حساب GitHub المحايد.
2. ارفع ملفات المشروع: من الجهاز بـ `git push`، أو من واجهة GitHub بالسحب والإفلات. مجلد `sources/` مستثنى من الرفع.
3. من *Settings → Pages* اختر *Deploy from a branch*، ثم الفرع `main` والمجلد `/ (root)`.
4. بعد دقيقة يصبح الموقع على `https://basira-site.github.io/basira`. وتأكد أن هذا الرابط مطابق لما وضعته في `SITE_URL` وفي إعدادات الروابط في Supabase.

## كيف تعمل المحادثة مع إنسان

1. يضغط الزائر «تحدّث مع إنسان».
2. **إذا لم يكن أي مشرف قد فعّل «متاح»** في لوحته، تظهر فورًا عبارة الاعتذار ومربع «اكتب استفسارك».
3. **إذا وُجد مشرفون متاحون** يصل كل واحد منهم بريد مستقل، ولا يرى أحد منهم بريد غيره. البريد لا يحتوي نص سؤال الزائر ولا أي معلومة عنه، فقط تنبيه ورابط. الرابط يفتح لوحة الإشراف بعد تسجيل الدخول، ويستلم المحادثة مباشرة، وأول من يدخل يستلمها.
4. يرى الزائر عدادًا تنازليًا (5:00) ويستطيع كتابة سؤاله أثناء الانتظار.
5. إذا مرت **5 دقائق** دون أن يستلم أحد المحادثة، يتحقق الخادم من مرور المهلة فعلًا، ثم تظهر عبارة الاعتذار ومربع «اكتب استفسارك وسيقوم أحد المشرفين بالرد عليك بأقرب وقت ممكن». ويُملأ المربع تلقائيًا بما كتبه الزائر.
6. يصل المشرفين بريد بوجود استفسار جديد. ويظهر الرد للزائر في «أسئلتي»، ويصله بريد بالرد إن كان قد أنشأ حسابًا.

ما معنى أن البريد «مشفر»؟ الرسالة لا تحمل أي محتوى أصلًا، والمحادثة نفسها لا تُقرأ إلا بعد تسجيل دخول المشرف عبر اتصال مشفر (HTTPS).

## الحساب الاختياري للزائر
لا يلزم الزائر أي تسجيل. إن أراد، يُنشئ حسابًا ببريده فقط دون اسم ولا كلمة مرور، بالدخول عبر رابط يصله على البريد. فائدة الحساب ثلاثة أمور: حفظ أسئلته والردود عليها، والاطلاع عليها من أي جهاز، وتنبيهه بالبريد عند رد المشرف.

## الأسئلة الشائعة
تُضاف تلقائيًا عندما يُجاب السؤال من المصادر ويحكم النموذج بأنه **ليس خاصًا**، أي لا يحتوي أسماء ولا ظروفًا شخصية ولا أماكن. ويُعرض بصياغة عامة. والأسئلة المتشابهة تُجمع في سؤال واحد ويزيد عدّاده. ومن لوحة الإشراف تستطيع تثبيت أي سؤال أو إخفاءه أو تعديل صياغته.

## لوحة تحكم المدير
تظهر للمدير وحده تبويبات إضافية في `/admin/`:

- **نظرة عامة**: أسئلة اليوم والأسبوع، ونسبة الأسئلة التي وُجد لها نص، والمحادثات التي استُلمت والتي فاتت، والاستفسارات التي بلا رد، ورسم بياني لآخر 14 يومًا، وقائمة بالأسئلة التي لم يُعثر لها على نص (تدلك على الكتب الناقصة).
- **تخصيص الموقع** مع معاينة مباشرة بحجم الحاسوب والجوال، ولا يرى الزوار شيئًا حتى تضغط «حفظ ونشر»:
  - الهوية: اسم الموقع، والعبارة التعريفية، ورفع الشعار وأيقونة المتصفح وتحديد حجم الشعار، ونص التذييل، ونافذة «عن الموقع».
  - الألوان: ستة أطقم جاهزة، وتسعة ألوان قابلة للتعديل، والتدرجات والزخارف والشعار الافتراضي تتلون منها تلقائيًا.
  - الخطوط: خط الموقع، وخط النصوص المقتبسة من الكتب.
  - الشكل: الزخرفة ووضوحها، واستدارة الحواف، والإضاءات الملونة، والحركات.
  - النصوص: كل عبارة يراها الزائر، ومنها عبارة الاعتذار ونص «اكتب استفسارك».
  - المزايا: إظهار أو إخفاء الأقسام والأزرار، وتفعيل «تحدّث مع إنسان»، والحسابات، وعدد الأسئلة الظاهرة.
- **الذكاء الاصطناعي والحدود**: اختيار النموذج، وتعليمات إضافية لأسلوب الإجابة، ورسالة عدم وجود نص، وعدد المقاطع التي يقرؤها النموذج لكل سؤال، ومهلة انتظار المشرف (5 دقائق افتراضيًا)، وحدود الاستخدام، والنشر التلقائي للأسئلة الشائعة أو انتظار موافقتك. أما قاعدة «لا إجابة إلا من المصادر» فثابتة في الخادم ولا تُلغى من اللوحة.
- **المصادر**: تفعيل أي كتاب أو إيقافه.
- **الأسئلة الشائعة**: اعتماد الأسئلة أو تثبيتها أو إخفاؤها أو حذفها.
